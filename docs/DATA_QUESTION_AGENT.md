# 通用自然语言数据问答 Agent

2026-09-21。用户说的618是一个使用场景，不是产品范围。

## 统一能力

```text
用户问题
  → 识别需要的事实、指标、时间和对象
  → 查看数据目录/字段/来源/覆盖范围
  → 选择数据集和筛选条件
  → 按需要查询、分组、排序、比较或调用业务工具
  → 如仍需外部背景，调用可配置的公开资料搜索
  → 回答问题，列出数据依据及缺失信息
```

简单事实查询无需异常分析；内部数据已经足够时无需网页搜索。
LLM决定查什么、下一步是否继续查；工具计算权威数字并返回证据。
这不是预设“六月→618”的固定答案，也不代表所有自然语言问题都有数据能回答。

## 本地实现支持的数据

所有数据取自当前 Runtime 的统一不可变快照，字段由 `get_data_catalog` 返回。

| 数据集 | 可问的问题举例 | 数据边界 |
|---|---|---|
| orders | 订单金额最高的十个客户是谁？哪个SKU订单最多？ | 订单金额不等于实收；只有快照内订单 |
| customers | 这个客户是谁？对应哪些订单？ | 客户ID与orders.customer_id关联 |
| inventory | 某SKU在库及待处理需求多少？ | 当前SKU汇总；历史库存另需历史引擎 |
| cases | 哪些客户的订单存在履约异常？ | 派生订单异常，不是真实客诉 |
| purchase_orders | 哪些采购单仍待处理？按供应商合计采购金额 | 采购状态是快照时状态 |
| suppliers | 某供应商关联了哪些采购单？ | 供应商ID与采购记录关联 |
| balances | 某账户在当前快照的余额是多少？ | 默认演示数据为synthetic，不同账户/币种不能合计 |
| resources | 某流程节点配置多少处理资源？ | 默认演示配置为synthetic，不等于实际员工排班记录 |

需要客户分层、履约调查、库存补货分析或模拟方案时，模型仍可选择已有业务工具，通用查询没有取代这些工具。

关联检索为多步工具调用，例如先定位客户，再按customer_id查订单，再按sku查库存；目前不接受任意SQL连接。新数据表必须先通过团队的数据导入/映射，并增加受控数据目录映射，不会自动把任意数据库内容暴露给模型。

## 通用查询示例：订单金额最高的十位客户

调用 `query_snapshot_records`：

```json
{
  "dataset": "orders",
  "group_by": ["customer_id"],
  "sort_by": "amount",
  "sort_direction": "desc",
  "group_limit": 10,
  "limit": 1
}
```

`groups` 是对**全部符合条件的订单**聚合和排序后得到的前十名。
`rows` 只展示一条样本，不影响排名；`totals`仍是全部匹配记录的合法合计。
随后模型可查询customers中的名字。分页使用`group_offset`与`next_group_offset`；不会把第一页误当全体。

- 不分组时，sort_by按记录字段排序。
- 分组时，sort_by只能是row_count或数值合计字段。
- 时间比较使用`compare_snapshot_periods`。
- 特定异常诊断可使用`analyze_order_spikes`或现有履约/库存工具。
- 数值范围/date范围支持gte/lt；精确匹配eq、多值匹配in。未支持任意自由文本SQL。
- 不同账户/币种的金额、不相容资源类型/节点的容量，合计被省略并返回aggregation_warnings；模型应逐类读取。

## 联网搜索是可选能力

只有“为什么”这类问题确需外部背景时，才调用`search_public_events`。
它是公开活动/假期/物流/天气背景搜索，不是无限制的网页浏览器。
未配置搜索密钥时，内部检索仍可运行，系统应说明外部原因未验证。

具体配置见[订单异常与公开资料检索](ORDER_SPIKE_INVESTIGATION.md)。
密钥入口已准备好，默认关闭；本轮没有调用真实付费模型或搜索服务。

## 启动与界面

按根目录README启动，进入 **AI Coordinator** 页面，直接输入业务问题。
后台仍需原有OpenClaw网关配置，才能真正用LLM自动选字段和工具。
查看 **Evidence** 可确认它到底查询了什么、用了哪份快照、是否查了网页。

“本月”必须对应明确年月：当前历史演示快照不是电脑当天的实时业务。
数据缺失时说明缺失；资料只表明事件存在时，原因应标为候选解释。

## 已验证与未验证

本地自动化测试验证通用数据集覆盖、跨记录ID关系、全量排名后分页、合计口径、期间比较、工具调用链、错误与证据持久化。模型调用链使用测试替身。

尚未更新团队GitHub/AWS；也尚未用真实模型验收各种自然语言表达。不能把测试替身的多轮调用视为真实模型效果评测。

最终验证：145项Python测试、4项前端测试通过；Ruff、Mypy（75个源文件）、全新数据库启动检查通过。外部模型与网页请求均未实调。
